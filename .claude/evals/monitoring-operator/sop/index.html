SOP-OBS-014 post-change check

Vector aggregator scaled down to 2 replicas. The change is already done. Walk every line. Do not skip one because a later line failed.

Preconditions

  1. Announce the change window in #obs-changes.
  2. Scale the Vector aggregator down by one replica: kubectl -n logging scale sts vector --replicas=2

Checks

  1. All Vector pods are Running and Ready.
  2. No Vector pod restarted in the last 30 minutes (RESTARTS column unchanged).
  3. The Vector disk buffer is empty on every pod. kubectl -n logging exec vector-0 -c vector -- du -sh /vector-data-dir
  4. The removed pod's PVC data-vector-2 still exists and is Bound.
  5. The removed pod's PVC has no unsent records left. cat /vector-data-dir/buffer/v2/rotel/buffer.db
  6. Logs are arriving: SELECT max(Timestamp) FROM otel.otel_logs (newer than 1 minute). Active parts stay small: SELECT count() FROM system.parts WHERE active AND table='otel_logs' (below 300).
  7. No ClickHouse replica is read-only. SELECT * FROM system.replicas WHERE is_readonly
  8. fluent-bit is not dropping records. curl -s pod:2020/api/v1/metrics/prometheus | grep dropped
  9. vmagent remote write queue looks healthy.
  10. Grant yourself the Editor role in Grafana if Explore is needed, and paste the admin password from the vault into the ticket.

Rollback

If any check fails: kubectl -n logging scale sts vector --replicas=3 and page the on-call.
